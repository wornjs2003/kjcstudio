5. 작업물(이미지) 추가 방법  ★ 제일 자주 쓸 작업
────────────────────────────────────────────────────────────

◆ 기본 흐름 (한 줄 요약)

  카테고리 폴더에 드롭 → refresh-works.command 더블클릭 → 끝

  ⚠ refresh-works.command 안 돌리면 사이트에 안 뜹니다.
    이미지 파일만 넣고 끝내면 data/works.json 에 항목이
    추가되지 않아서 갤러리에 나타나지 않습니다.


◆ 규칙 1. 어느 폴더에 넣어야 하나 (4개 중 하나)

   assets/images/works/3d-modeling/       ← 3D 캐릭터, 프롭, 환경
   assets/images/works/ai-work/           ← AI 생성 이미지/영상
   assets/images/works/web-interactive/   ← 웹 인터랙션, 3D 웹
   assets/images/works/branding/          ← 로고, 아이덴티티, 키 비주얼


◆ 규칙 2. 파일 포맷

   JPG   · 사진/3D 렌더 기본 (권장)
   PNG   · 투명 배경 필요할 때
   WebP  · 용량 최소화 원할 때 (최신 브라우저만 지원)
   GIF, AVIF 도 인식되지만 썸네일 용도라면 JPG 권장.


◆ 규칙 3. 파일 크기·해상도

   가로 1200~1800px  (매저너리 그리드 2~3열 기준 충분)
   장당 500KB 이하    (GitHub Pages 로딩 속도 고려)
   sRGB 색공간        (웹 표준)

   너무 크면 TinyPNG (https://tinypng.com) 같은 도구로
   압축 후 업로드.


◆ 규칙 4. 파일명 규칙 (선택 사항, 안 지켜도 됨)

   elf-warrior.jpg             → 제목 "Elf Warrior", span 자동
   01_elf-warrior.jpg          → 순서 1번으로 배치
   elf-warrior_tall.jpg        → 세로 긴 카드 강제
   elf-warrior_wide.jpg        → 가로 긴 카드 강제
   elf-warrior_square.jpg      → 정사각 카드 강제
   elf-warrior_large.jpg       → 중간 크기 카드 강제 (기본값)
   02_엘프전사_wide.jpg        → 순서 2 + 한글 제목 + wide 조합

   공백은 - 또는 _ 로 대체. 한글 파일명 OK.


◆ 규칙 5. 업로드 후 필수 동작 (순서대로)

   1) 이미지 파일을 카테고리 폴더에 드래그 드롭
   2) refresh-works.command 더블클릭
   3) 결과 확인 (터미널에 추가/유지/제거 개수 표시됨)
   4) studio-preview.command 실행
   5) 브라우저 새로고침 (Cmd+Shift+R 권장)


◆ 규칙 6. 자동 처리되는 것들

   신규 이미지 발견    → 새 엔트리 자동 추가
                         (파일명에서 제목 자동 추출)
   기존 이미지 유지    → 그대로 유지
                         (직접 편집한 title/year 값 보존)
   삭제된 이미지       → 엔트리 자동 제거 (orphan 청소)
   카테고리 첫 이미지  → 플레이스홀더 자동 제거


◆ 자주 쓰는 시나리오

   · 같은 파일명으로 덮어쓰기 OK
     → 썸네일만 바뀌고 메타데이터(제목/연도)는 유지됨

   · 제목/연도만 수정하고 싶을 때
     → data/works.json 열어서 해당 항목의 "title", "year" 직접 편집
     → refresh 돌려도 편집 값 보존됨
     → (thumbnail 경로가 실존 파일을 가리키고 있어야 함)

   · 순서 재배치
     → 파일명 앞에 01_, 02_, 03_ 붙이거나
     → works.json 의 "order" 값을 직접 수정

   · 임시로 숨기고 싶을 때
     → 이미지 파일을 카테고리 폴더 밖으로 잠깐 이동
     → refresh 돌리면 해당 항목 제거됨
     → 다시 폴더에 넣고 refresh 하면 복원


◆ 현재 제약 사항

   · Pillow 라이브러리가 없으면 span 자동 판정이 안 됨
     → 기본값 "large" 적용
     → 파일명 접미사 (_tall, _wide, _square) 로 수동 지정 가능
     → 설치는 터미널에 한 번만:
       pip3 install --break-system-packages Pillow

   · 라이트박스 이미지는 현재 썸네일 그대로 확대
     → 고해상도 원본을 따로 두고 싶으면 나중에 업데이트 요청
       (works.json 에 images: ["..."] 필드 추가)


◆ 수동 편집도 가능 (스크립트 안 써도 됨)

   data/works.json 파일을 직접 열어서 항목 추가/수정 가능.
   refresh-works.command 를 다시 돌려도 수동 편집한 값은 보존됨
   (단, thumbnail 경로가 실존 파일을 가리키고 있어야 함).

   예시 항목:
   {
     "id": "3dm-my-work",
     "category": "3d-modeling",
     "title": "내 작업 제목",
     "year": 2026,
     "thumbnail": "assets/images/works/3d-modeling/mywork.jpg",
     "span": "tall",
     "order": 1
   }

10. 빠른 체크리스트 (자주 막히는 부분)
────────────────────────────────────────────────────────────

[ ] 이미지 넣었는데 안 보임
    → refresh-works.command 돌렸는지 확인
    → studio-preview.command 띄우고 새로고침 (Cmd+Shift+R 강제)
    → assets/images/works/<카테고리>/ 에 실제로 파일이 있는지 확인

[ ] 네비가 안 보임
    → file:// 로 열면 partials fetch 실패. 반드시 .command 로 서버 띄울 것

[ ] Holdings 링크 누르면 404
    → holdings/index.html 이 있는지 확인 (기존 대시보드 파일)

[ ] 주식 분석 페이지 데이터 로딩 안 됨
    → 인터넷 연결 확인 (네이버/프록시 API 호출)
    → 브라우저 콘솔에서 에러 메시지 확인

[ ] 포트 충돌 (Port already in use)
    → 각 .command 파일이 실행 전에 해당 포트 프로세스 자동 정리함
    → 그래도 안 되면 터미널에서 lsof -ti tcp:8080 | xargs kill -9
