### 상승·하락 색은 공용 클래스가 정한다 — 덮어쓰지 않는다 (2026-09-15)

상승 빨강 · 하락 파랑 · 보합 검정은 이미 룰이고, 변수(`--kh-up` · `--kh-down` ·
`--kh-flat`)와 공용 클래스(`.kh-up` · `.kh-down` · `.kh-flat`, `css/frame.css`)가
그것을 담고 있다. **구역 CSS 에서 그 위에 `color` 를 얹지 않는다.**

    /* 하지 않는다 — .kh-up 보다 우선순위가 높아 색이 묻힌다 */
    .kh-mkt b { color: var(--kh-text-primary); }

    /* 이렇게 — 굵기·크기만 주고 색은 건드리지 않는다 */
    .kh-mkt b { font-weight: 500; }

`.어떤것 b` 는 클래스 하나짜리인 `.kh-up` 을 이긴다. 그래서 `<b class="kh-up">` 이
검정으로 나온다. 2026-09-15 에 장 상태 줄의 상승·하락 종목 수와 현물·선물 값이
전부 검정으로 나왔고, 원인이 이것이었다.

- 색을 꼭 줘야 하는 자리가 섞여 있으면 **그 자리에만 클래스를 만든다**
  (예: `.kh-mkt b.kh-mkt-note`). 전체를 덮어놓고 예외를 뒤에 다는 방식은 쓰지 않는다
- 새 CSS 를 쓸 때 `.클래스 태그 { color: … }` 형태가 나오면, 그 안에 색 클래스가
  붙은 요소가 들어올 수 있는지 먼저 본다



### 차트 칸의 좌우 끝은 반드시 맞는다 (2026-09-18 지시)

재권님 말씀 그대로다.

> 캔들차트의 왼쪽 오른쪽 그려지는 끝과 보조지표들은 라인이 맞아야 돼
> 임의로 조절되면 안돼

가격 · 거래량 · MACD · RSI 는 칸이 나뉘어 있어도 **같은 시간축을 본다.**
봉 하나와 그 아래 지표가 세로로 안 맞으면 **지표를 읽을 수 없다.**

**어긋나는 원인은 오른쪽 가격축 폭이다.** 라이브러리가 값의 글자 수에 맞춰
자동으로 잡으므로 **아무도 손대지 않아도 저절로 갈린다.**

    가격   1,402,000   열 자     축이 넓다  → 그림이 일찍 끝난다
    RSI        49.82   다섯 자   축이 좁다  → 그림이 더 간다

**모든 칸에 같은 축 폭을 못 박는다** — `rightPriceScale.minimumWidth`.
칸마다 차트를 따로 만들기 때문에 한 칸만 고치면 그 칸만 움직인다.

**무엇이 검사하나** — 그릴 때마다 각 칸의 그림 폭을 재서 1px 이라도 다르면
차트 오른쪽 위에 빨간 표시가 뜨게 한다.

    좌우 끝이 어긋남 — 1204 · 1198 · 1204px

### 지표를 켜고 꺼도 차트 크기가 바뀌지 않는다 (2026-09-18 지시)

재권님 말씀이다.

> 뭔가 룰이 잘못됬는데... 뭐하나 추가할때마다 이런게 생기면 안되

**이것은 루트 `CLAUDE.md` 「보는 것을 바꿔도 자리는 그대로다」 의 한 자리다.**
그 룰이 화면 전체를 말하고, 여기는 **차트 안쪽**을 말한다. 2026-09-18 에
차트에만 적용했다가 투자자 정보에서 같은 문제가 또 났다.

**겹쳐 그리는 것을 켜고 끌 때 세로 범위가 바뀌면 안 된다.** 켤 때마다 봉이
커졌다 작아지면 **무엇이 바뀐 것인지 읽을 수 없다.** 위 「좌우 끝」 과 짝이다 —
그것은 가로, 이것은 세로다.

**겹침은 세로 축 계산에서 뺀다** — `js/chart.js` 의 `NO_SCALE` 을 쓴다.
한 곳에 두었으므로 **새 겹침을 붙일 때도 그것을 쓴다.**

    const NO_SCALE = { autoscaleInfoProvider: () => null };

**2026-09-18 하루에 같은 자리가 세 번 깨졌다.**

    볼린저를 켜면 봉이 작아졌다
    이동평균(MA60)을 켜면 차트 크기가 바뀌었다
    매물대를 켜면 화면이 조절됐다

**셋 다 새 지표를 붙이면서 났다.** 그때마다 따로 고쳤고, 다음 지표에서 또 났다.

**왜 되풀이됐나** — 가로 룰은 **문서에 절이 있고 검사가 있어서** 안 깨졌는데,
세로 룰은 **코드 주석에만 있고 검사가 없었다.** 주석은 그 파일을 여는 사람만 본다.
이 문서가 스스로 정한 「검사에 걸리게 쓴다」 가 이 자리에서 안 지켜지고 있었다.

**무엇이 검사하나** — 켜기 직전에 세로 범위를 재 두고(`readScale`), 켠 뒤 견줘
**1% 넘게 달라지면 차트에 빨간 표시**를 낸다(`checkScale`, `js/chart.js`).
좌우 경고 바로 아래 칸에 뜬다.

    세로가 움직임 — 251359~266164 → 250976~266237 (3.1%)

**일부러 어긋나게 해서 뜨는 것까지 봤다** — 볼린저의 `NO_SCALE` 을 임시로 빼고
켜 보니 위 문구가 나왔다. **늘 안 뜨는 검사는 없는 것과 같다.**

**이동평균은 이 검사에 늘 걸리지는 않는다.** 선이 봉의 고가~저가 **안쪽**이면
축이 안 움직이기 때문이다. 2026-09-18 의 MA60 건은 그 선이 봉 범위 **밖**으로
나가는 구간이었다. **「검사가 안 도네」 로 읽지 않는다** — 안 움직였으면
안 뜨는 것이 맞다.

## 「자세히」 · 「더보기」 는 모달로 연다 (2026-09-21 지시)

**화면을 벗어나지 않는다.** 누르면 그 자리에 모달이 뜬다.

    하지 않는다   <a href="./news.html">더보기</a>      ← 화면이 통째로 바뀐다
    이렇게        <button data-modal="news">더보기</button>

**대상은 「목록에서 더 보러 가는 자리」다 — 「자세히」 · 「더보기」.**
**무엇이 아닌지가 아니라 무엇인지로 적는다.** 제외로 적으면 새 링크가
생길 때마다 「이건 예외인가」 를 따져야 하고, **안 따지면 저절로 대상이 된다.**

| | 예 | |
|---|---|---|
| **대상** | 「자세히」 · 「더보기」 | 목록에서 **더 보러 간다** |
| 메뉴 | `nav.kh-cat` — 홈 · 관심 · 국내 … | **모달** (2026-09-21 지시 · 아래) |
| 돌아가기 | 종목 화면의 **「← 목록」** | 더 보러 가는 것이 아니다 |

**메뉴도 모달로 간다 (2026-09-21 지시).** 처음에 「갈래를 고르는 것은 화면
이동이 맞다」 로 적었는데 재권님이 뒤집으셨다. 말씀 그대로다.

> 지금은 데일리분석 을 누르면 **모델이 올라오고** 그다음에 데일리 분석이랑
> 필요한 **메인페이지에 공간을 만든다** 로 이해하면 돼

    1단계   메뉴를 누르면 **모달**
    2단계   그 내용이 들어갈 **칸을 메인에 만든다**

**「메뉴를 모달로 바꾸면 그 화면에 갈 길이 없어진다」 가 처음에 화면 이동으로
적은 이유였는데, 2단계가 그것을 푼다** — 내용이 메인에 들어오면 그 페이지가
따로 필요 없어진다.

**1단계만 하고 페이지는 그대로 둔다.** 주소로 직접 들어가면 여전히 열려야 한다.

**「자세히 ›」 는 이 결정과 무관하다.** 그것은 **모달이 호가·체결을 못 담아서**
화면으로 가는 것이고, 메뉴는 **담을 수 있어서** 모달로 오는 것이다.

**「← 목록」 이 이 구분을 만들었다 (2026-09-21 · 홈페이지_정리 지적).**
처음에 「메뉴는 그대로 둔다」 로 적었는데, 그러면 **메뉴가 아닌 「← 목록」 이
대상이 되어 모달로 바꿔야 한다**는 말이 된다. 제외 목록은 그렇게 샌다.

### 「모달이 담을 수 있는가」 로 가른다 (2026-09-21)

**셋을 같은 성격으로 묶은 것이 틀렸다.** 처음에 `kh-fold` · `kh-sec-more` ·
`kh-w-more` 를 함께 세고 「`grep` 이 0 이어야 한다」 고 적었는데,
**`kh-fold`(「자세히 ›」)를 모달로 바꾸면 종목 화면에 아예 못 간다.**

| | 예 | 어떻게 |
|---|---|---|
| **목록 → 그 목록의 전부** | 뉴스·공시 「더보기」 | **모달** |
| **모달 → 더 큰 화면** | 종목 「자세히 ›」 | **화면 이동이 맞다** |

**첫 화면에 종목 모달이 이미 있다.** 종목을 누르면 뜬다. 「자세히 ›」 는
**그 모달보다 큰 것**으로 가는 길이다.

**재서 확인했다 (2026-09-21)** — 모달과 종목 화면이 같은 `mountStockView` 를
쓰는데, **호가와 체결은 `stock.html` 에만 있다.** 모달이 그 둘을 안 담는다.

**「제외로 적으면 샌다」 의 뒷면이다.** 포함으로 적어도 **「목록에서 더 보러
가는 자리」 라는 정의에 이 한 줄이 문면상 들어온다.** 제외 목록은
「안 따지면 저절로 대상이 된다」 가 문제였고, 여기는 **「따져도 대상으로
읽힌다」** 였다. `주식페이지_개발2` 가 대상을 세다가 찾았고,
`주식페이지_개발` 이 「모달로 바꾸면 종목 화면에 못 간다」 를 짚었다.

**기계는 이것을 못 가른다.** 「모달이 담을 수 있는가」 는 사람이 본다.

**무엇이 검사하나** — 아직 도구가 없다. 세는 방법은 이것이다.

    grep -rn 'href' holdings/*.html | grep '더보기'

**「자세히 ›」 는 세지 않는다** — 위 표의 아랫줄이라 화면 이동이 맞다.

**`index.html` 만 보지 않는다.** 2026-09-21 에 그렇게 세어 **종목 화면의
「더보기」 하나를 통째로 놓쳤다.** 대상인 「더보기」 는 클래스가 둘로 갈려 있다 —
`kh-sec-more`(첫 화면) · `kh-w-more`(종목 화면). **같은 성격인데 이름이 다르다.**
**0 이 나와야 다 옮긴 것이다.**

**`kh-fold`(「자세히 ›」)를 여기 넣지 않는다.** 위 표의 아랫줄이다.
2026-09-21 에 셋을 한 묶음으로 적었다가 뺐는데, **이 문단에 그대로 남아
바로 위 줄과 어긋나 있었다** — `주식페이지_개발` 이 찾았다.
**절을 새로 넣을 때 아래 옛 문단도 같이 본다.**

> **줄 번호를 여기 적지 않는다.** 2026-09-21 에 잰 값이 **같은 날 안에 낡았다** —
> 다른 세션이 그 파일을 고치고 있어서 세 자리가 전부 밀렸다.
> 「세면 나오는 값은 본문에 적지 않는다」 가 **남이 만지는 파일에서는 더 빨리** 온다.

### 데일리분석은 진입점부터 만든다

「더보기」가 전부 `news.html` 로 가고 **`daily.html` 로 가는 것이 하나도 없다**
(2026-09-21 확인). 메뉴에는 있는데 **본문에서 들어가는 길이 없다.**

**화면을 만들기 전에 들어가는 길부터 만든다.** 길이 없으면 만들어도 아무도 못 본다.

### 모달이 원본이고, 목록·카드는 거기서 덜어낸 일부다

같은 것을 두 번 만드는 것이 아니다. **모달에 다 있고, 목록은 그중 몇 줄만 보여준다.**

    모달    그 항목의 전부
    목록    거기서 제목·시각 정도만 덜어낸 것

그래서 **새 항목이 생기면 모달에 먼저 넣는다.** 목록에만 넣으면 눌렀을 때 빈 자리가 된다.
「같은 값은 한 곳에만 둔다」 와 같은 자리다 — 어느 쪽이 원본인지 정해 두지 않으면
두 곳을 따로 고치게 된다.

### 최적화는 「멈춘다」 가 아니라 「늦춘다」 다

**모달을 멈추면 같이 죽는다.** 모달은 목록 폴링에 **얹혀 있다** — 목록이 받아온 값을
모달에 넘기는 구조다. 찾는 방법은 이것이다.

    grep -n "stockModal" holdings/js/home.js

거기 주석에 이유가 적혀 있다 — **모달이 따로 받으면 두 자리의 숫자가 어긋나고
KIS 를 겹쳐 부르게 된다.**

| 모달 상태 | 어떻게 하나 |
|---|---|
| **열림** | 그 종목을 받는 목록에 넣고 **자주**. 나머지는 **늦춘다** |
| **닫힘** | **보이는 줄만** 한 번 |

**「나머지를 멈춘다」 가 아니다.** 멈추면 모달이 값을 못 받는다.

**효과는 붙인 뒤에 잰다 (2026-09-21 지시).** 「호출이 줄어든다」 는 지금 **추정**이다.
여기에 줄어든 양을 적지 않는다 — 재고 나서 적는다.
「대보기 전에 재고 나서 적는다」 와 같다.

## 상단 메뉴 (2026-09-14 추가)

첫 화면(`index.html`)과 종목 화면(`stock.html`)은 루트 메뉴를 쓴다. 네 구역이 같다.

    <body data-nav="holdings" data-site-root="../">
    <div id="site-nav"></div>                        화면 맨 위
    <script src="../assets/js/main.js"></script>     </body> 직전

`../assets/css/nav.css` 의 `.site-nav` 는 `position:fixed` 라 그냥 두면 화면 맨 위를
덮는다. `css/frame.css` 끝에서 자리를 맞춰 두었다 — `.kh-app` 에 `padding-top`,
세로 아이콘바 기준점, 관심 사이드바 높이 셋이다.

**세로 아이콘바 규칙은 `@media (min-width: 901px)` 로 가둬야 한다.** 좁은 화면에서
이 바는 화면 아래쪽 가로 막대(`top:auto`)로 바뀌는데, 파일 끝에 그냥 적으면 나중에
선언되어 그것을 덮어버리고 막대가 위로 올라와 공지 배너를 가린다.

`analysis/index.html` 과 `roadmap.html` 은 아직 `js/h-page.js` 가 넣는 자체 메뉴를 쓴다.

## 데이터 규칙 (중요)
- **예시 데이터를 화면에 두지 않는다.** 받아온 값만 보여주고, 없으면 없다고 적는다
- 이유: 그럴듯한 숫자가 박혀 있으면 연결이 안 된 건지 시세가 그런 건지 구분할 수 없다 (2026-09-11 지시)
- 빈 값 표기: `불러오는 중` (요청 중) · `—` (받아올 곳이 아직 없음) · `불러오지 못함` (실패)
- 아직 붙이지 않은 기능은 **빨간 바탕 칸**으로 「무엇이 비어 있는지 + 무엇을 붙이면
  채워지는지」 를 화면에 적는다 (루트 `CLAUDE.md` 「아직 안 정해진 자리는 빨간
  바탕으로 남긴다」). **공용 컴포넌트는 없다** — 데일리 화면은 `.kh-dl-todo`
  (`css/daily.css`), 첫 화면은 「연결 예정」 문구로 각자 적는다
- `js/data/market.js` 에는 목록(코드·이름·섹터)만 둔다. 시세·재무는 서버에서 받는다

### 받을 수 없는 것은 자리도 만들지 않는다 (2026-09-17 지시)

위의 「무엇을 붙이면 채워지는지 적는다」와 갈라지는 자리다. **둘을 가르는 것은
「받을 곳이 있느냐」**다.

| | 화면에서 | 예 |
|---|---|---|
| **붙일 수 있는데 아직 안 붙였다** | 자리를 두고 **무엇을 하면 채워지는지 적는다** | WTI·금 — 「거래소 신청 필요」 |
| **받을 곳이 없다** | **자리를 만들지 않는다** | 다우존스 — 증권사 두 곳 다 없다 |

재권님 말씀 그대로다 — **"받을 수 없는 지수는 메인 UI 상에서도 없애고 만들지 않는다."**

**왜** — 「연결 예정」이 오래 붙어 있으면 그게 곧 올 것처럼 읽힌다. 받을 곳이
없는데 자리만 있으면 볼 때마다 「저건 언제 되나」를 묻게 되고, 답은 「안 된다」다.
빈 자리가 계속 눈에 걸리는 것이 「없는 줄 아는 것」보다 나쁘다.

**뺄 때는 왜 뺐는지 남긴다.** 코드 주석과 `docs/data-sources.md` 두 곳에 적는다.
안 적으면 다음 사람이 「빠졌네」 하고 다시 만든다. 실제로 다우존스는 이미
두 번 찾아봤다 — 조사 기록이 없었으면 세 번째가 있었을 것이다.

**나중에 받을 수 있게 되면 되살린다.** 뺀 것은 지운 것이 아니다.

## 시세 표기 규칙 (중요)

**정규장 중에는 KRX 값, 장이 끝나면 넥스트레이드 값.** (2026-09-12 지시)

| 시각 (한국) | 기준 | 이유 |
|---|---|---|
| 평일 09:00 ~ 15:30 | `J` (KRX) | 네이버·증권사 앱과 같은 숫자여야 한다 |
| 그 외 전부 (마감 후·개장 전·주말) | `UN` (통합) | 넥스트레이드에서 더 움직인 값이 있으면 그것을 쓴다 |

- 장 마감 후 넥스트레이드에 변동이 있으면 그 값을 보여주고, **다음 장이 열릴 때까지 유지**한다
- 넥스트레이드에 거래가 없는 종목은 통합(`UN`)이 **KRX 종가를 그대로 돌려준다.**
  2026-09-12 에 직접 호출해 확인했다 — 삼성전자우 193300 · 흥아해운 1878 · 동양3우B 5750 (`NX` 는 셋 다 0).
  그래서 종목마다 두 번 부를 필요가 없다
- 구현: `server/kis_proxy.py` 의 `quote_market_div()` · `worker/kis-worker.js` 의 `quoteMarketDiv()`.
  **두 곳이 같은 판정을 해야 한다.** 로컬과 배포본의 숫자가 달라지면 안 된다
- **차트는 통합(`UN`) 고정.** 과거 봉이라 "지금 몇 시인가"를 따질 일이 없다
- 공휴일은 가리지 못한다. 휴장일 낮에는 KRX 기준이 되는데, 어느 쪽을 봐도 전일 값이라 문제되지 않는다

**왜 이 규칙이 생겼나**: 2026-09-11 에 시세를 통합(`UN`) 고정으로 바꿨더니, 장 마감 후
넥스트레이드 값이 그대로 남아 네이버와 숫자가 어긋났다 (9/12 토요일 기준 삼성전자
KRX 259,500 vs 통합 262,000). 실시간성은 살리되 정규장 중에는 남들과 같은 값을 보도록 나눴다.

**감시 대상은 코스피 시가총액 상위 200종목. 텔레그램은 관심종목 8개만.**

  종목별로 물으면 하루 57,600건이라 한도(약 20,000건)를 넘긴다. 지금 방식은 약 1,150건이다
- 텔레그램은 **관심종목만**, 공시 종류는 **가리지 않고 전부** 보낸다

  `WATCH_CODES` 와 `notify()` 를 고친다
- `WATCH_CODES` 는 `js/data/market.js` 의 `WATCHLIST` 와 같아야 한다. 한쪽만 고치면 어긋난다
- 처음 켜는 날 쌓여 있던 공시는 보내지 않는다. 안 그러면 수십 건이 한꺼번에 날아간다

## 주요 일정 규칙 (2026-09-15 지시)

첫 화면 관심종목 아래의 「주요 일정」 칸이 무엇을 담는지 정한다.

### 무엇이 주요 일정인가 — 거시 지표다

| 묶음 | 예 |
|---|---|
| **실적 발표** | 기업 실적 발표일 · IR 개최 |
| **각 나라별 물가 일정** | 한국 소비자물가 · 미국 CPI · PCE 등 |
| **금리 일정** | 한국은행 금통위 · 미국 FOMC 등 |
| **경제지표** | 고용 · 성장률 등 발표일 |
| **한국 수출 데이터** | 수출입 동향 발표일 |

**종목 하나에만 해당하는 일정은 주요 일정이 아니다.** 배당기준일 · 주주총회 ·
유상증자 · 무상증자 · 액면분할 · 공모주 청약 · 보호예수 해제는 **그 종목 화면의
「다가오는 일정」**에 둔다. 여기는 시장 전체가 같이 보는 것만 올린다.

실적 발표만 양쪽에 걸친다. 시장 전체로는 "이번 주 실적 시즌", 종목 화면에서는
"이 종목 발표일" 로 쓴다.

### 언제 것을 보여주나

**앞으로 2주 안에 있을 것만 보여준다.** 오늘부터 14일이다.

- 지난 일정은 안 보여준다. 일정은 "앞으로 뭐가 있나" 를 보는 칸이다
- 2주가 넘으면 지금 당장 할 일이 아니라 자리만 차지한다
- 기간을 바꿀 일이 생기면 상수 하나로 두고 거기만 고친다

### 늘릴 때

**주요 일정에 묶음을 추가하면 그 관련 정보도 함께 붙는다.** 예를 들어 「금리 일정」을
넣으면 금통위 날짜만이 아니라 현재 기준금리·직전 변동도 함께 보여준다. 날짜만
있으면 그게 무슨 뜻인지 알 수 없다.

지금은 일정표의 `note` 에 확인된 것만 적어 두었다 — "경제전망(SEP) 함께 발표",
"한국시각 밤 9:30" 같은 것이다. **현재 기준금리 값은 아직 붙이지 않았다.**
받아올 곳을 확인하지 못했다 (2026-09-15).

### 어디서 가져오나 (2026-09-15 조사 · 붙임)

| 묶음 | 출처 | 상태 |
|---|---|---|
| 금리 · 물가 | `data/market-calendar.json` | **붙였다.** FOMC · 금통위 · 미국 CPI |
| 실적 발표 | OpenDART 「기업설명회(IR)개최」 | **붙였다.** 이미 받던 공시에서 골라낸다 |
| 한국 소비자물가 · 수출 데이터 | ? | **아직 못 찾았다** |
| 미국 PCE · 고용지표 | ? | **아직 못 찾았다** |

**금리·물가는 API 가 아니라 파일로 둔다.** FOMC·금통위·CPI 는 1년치 날짜가 미리
공개되고, 일정 전용 API 도 거의 없다 (한국은행 공표일정과 금통위 일정은 HTML
페이지다). 1년에 한 번 정리하면 끝날 것을 매일 부르는 것은 과한 구조다.

날짜는 공식 출처에서 직접 받았다 — `federalreserve.gov` · `bok.or.kr` ·
`bls.gov`. 파일 안에 확인한 곳과 **아직 못 찾은 것**을 함께 적어 둔다.
확인하지 못한 날짜는 적지 않는다. 빈 칸이 지어낸 날짜보다 낫다.

**일정표가 바닥나면 화면이 스스로 말한다** — "일정표를 갱신할 때입니다".
빈 칸만 두면 고장인지 일정이 없는 건지 알 수 없다.

### 실적 발표는 걸러서 보여준다 (2026-09-15 지시)

IR 은 하루 평균 **15건**쯤 올라온다 (5영업일 실측: 14·19·7·13·21). 그대로 두면
2주에 약 150건이 되어 금리·물가 일정이 그 아래로 묻힌다.

**관심종목 · 코스피200 · 코스닥150 에 드는 것만 남긴다.** 관심종목은 지수에 없어도
남긴다 — 담은 종목이면 규모와 무관하게 봐야 한다. 2026-09-15 기준 14건 중 7건이
남았다.

지수 구성종목은 **네이버**에서 하루 한 번 받는다. KIS 에는 구성종목을 주는 API 를
찾지 못했다.

    코스피200   entryJongmok.naver?type=KPI200   199종목
    코스닥150   entryJongmok.naver?type=KQI150   149종목

`KQI150` 은 문서에 없는 이름이라 후보를 직접 호출해 찾았다
(`KDQ150`·`KOSDAQ150`·`KQ150` 은 빈 결과). 분기에 한 번 바뀌는 값이라 하루 한 번만
받는다. `server/dart.py` 의 `INDEX_LISTS` 와 `worker/kis-worker.js` 가 같아야 하고,
`tools/check-kis-consts.py` 가 대조한다.

화면에서는 공시 칸과 같은 모양의 **필터 칩**으로 나눠 본다 — 전체 · 관심종목 ·
코스피200 · 코스닥150 · 금리 · 물가. 실제로 들어온 것만 칩이 생긴다.
