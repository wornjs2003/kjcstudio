## 2-1. 호출 한도 — 우리는 얼마나 쓰고 있나

### 한국투자증권 (지금 쓰는 곳)

| | 값 | 출처 |
|---|---|---|
| 기본 한도 | **초당 20건 (20 TPS)** | 2026-08-31 캠페인 보도자료 |
| 확대 한도 | **40 ~ 100 TPS** | 최근 5영업일 일평균 거래대금 조건 충족 시, 2026-12-31 까지 |
| 신청 기한 | 2026-10-30 | 캠페인 종료일 |
| 초과 시 | `EGW00201` 초당 거래건수를 초과하였습니다 | 오류코드 |

**우리 서버는 한도를 10 TPS 로 가정하고, 그중 1/10 인 초당 1건만 씁니다.**
실제 한도가 20 TPS 이므로 **지금 쓰는 양은 한도의 5%** 입니다.
(`server/kis_proxy.py` 의 `KIS_LIMIT_PER_SEC` · `BUDGET_RATIO` 두 줄로 조절합니다)

여유가 많으므로 갱신 주기를 당기거나 종목을 늘릴 수 있습니다. 다만 실시간이 꼭 필요한
화면이 아니라면 지금 간격(15초)도 충분합니다.

**공식 문서에서 확인하지 못한 것**: KIS Developers 포털과 공식 GitHub 저장소 어디에도
초당 건수가 숫자로 적혀 있지 않았습니다. 위 20 TPS 는 **보도자료 기준**입니다.
모의투자 한도는 자료마다 1건/초 ~ 5건/초 로 엇갈려 **확인하지 못했습니다.**
정확한 값은 포털 로그인 후 또는 1:1 문의로 확인해야 합니다.

### 한국투자증권 — 파라미터 이름에 속지 말 것 (2026-09-14)

`FID_INPUT_HOUR_1` 은 **API 마다 뜻이 다릅니다.** 이름만 보면 둘 다 "입력 시각" 입니다.

| 어디 | 뜻 | 예 |
|---|---|---|
| 종목 분봉 `inquire-time-itemchartprice` | **기준 시각** | `"153000"` → 15:30 기준 과거 30개 |
| 지수 분봉 `inquire-time-indexchartprice` | **초 단위 간격** | `"300"` → 5분 간격 하루치 99건 |

지수 분봉에 `"150000"` 을 넣으면 시각으로 읽히지 않고 **날짜별 요약**이 돌아옵니다.
`tr_id` 는 `FHKUP03500200` 입니다.

**공식 문서에 이 값이 적혀 있지 않습니다.** 여러 값을 직접 넣어 찾았습니다. 그전에는
"지수 분봉은 받을 수 없다" 고 판단했고 지수 차트를 포기할 뻔했습니다. 이 항목이 없으면
같은 결론으로 되돌아갑니다.

### 토스증권 — 한도를 가장 투명하게 공개합니다

엔드포인트 묶음별로 나눠 명시하고, 응답 헤더 `X-RateLimit-Limit` 으로 현재 한도를
확인할 수 있습니다. 초과하면 `429` 와 `Retry-After` 로 언제 다시 부를지 알려줍니다.

| 묶음 | 초당 |
|---|---|
| MARKET_DATA_CHART (차트) | 20 |
| MARKET_DATA (시세) | 15 |
| ORDER (주문) | 10 |
| AUTH · ASSET · STOCK · CONDITIONAL_ORDER | 5 |
| ACCOUNT (계좌) | 1 |

웹소켓은 **계정당 동시 연결 2개**, **연결당 구독 100건**, 구독 선언 5회/초 입니다.
일일 제한은 명시되어 있지 않습니다.

### 다우존스 · WTI · 금 — 2026-09-17 조사

앞의 두 줄은 「더 찾아보면 나올 것」처럼 읽혔는데, 실제로 파고들어 보니
**막힌 이유가 서로 다릅니다.**

**WTI · 금 — 거래소 신청이 필요합니다**

해외선물 시세 API 는 경로도 요청도 맞았습니다. 권한만 없었습니다.

```

    SRS_CD = CLZ26 (WTI) · GCZ26 (금)

→ {"rt_cd":"1","msg1":"NYMEX SUB거래소 신청 계좌가 아닙니다","msg_cd":"EGW00551"}
```

거래소별로 따로 신청해야 합니다 — WTI 는 **NYMEX**, 금은 **COMEX**.
신청이 유료인지 무료인지는 확인하지 못했습니다.

**다우존스 — 받을 곳이 없습니다**

## 4. 성격에 맞게 나눈다면

같은 항목을 두 곳에서 받으면 값이 어긋납니다. 실제로 삼성전자 PER 이
한국투자증권 39.91 배, 네이버 11.64 배로 **71% 차이**가 났습니다. 계산 기준이
서로 달라서 둘 다 틀린 값은 아니지만, 화면에 섞여 나오면 어느 쪽이 맞는지 알 수 없습니다.

그래서 **항목마다 출처를 하나만 정하고, 화면에 어디서 온 값인지 적는다**는 원칙이
필요합니다.

> **2026-09-17 정정.** 이 표가 두 줄 틀려 있었습니다. 둘 다 「KIS 로는 안 된다」고
> 적어 놓았는데 **실제로는 됩니다.**
>
> | 고치기 전 | 사실 |
> |---|---|
> | 해외지수·환율 → 야후 (국내 계약으로는 못 받음) | KIS 로 받아집니다. 이미 그렇게 쓰고 있습니다 |
> | 투자자별 매매동향 → 네이버 (KIS 무료 범위 밖) | 종목별은 KIS 로 됩니다 |
>
> **표만 보면 네이버·야후로 가게 됩니다.** 그런데 이 문서 자신이 네이버를
> 「예고 없이 막힐 수 있음」으로 적어 두었고, 공개 프록시 네 곳이 한꺼번에 죽은
> 선례도 아래에 있습니다. **표 한 줄 때문에 공식 출처를 두고 불안정한 쪽으로
> 갈 뻔했습니다.**
>
> 두 번 다 **같은 문서 안에 반박이 이미 있었습니다** — 해외 건은 `kis_proxy.py`
> 주석이, 투자자별은 이 문서 본문(「종목별은 정상」)이 그랬습니다. 표와 본문이
> 갈리면 표만 읽힙니다. **고칠 때 둘 다 고쳐야 합니다.**

| 화면 항목 | 받아올 곳 | 왜 |
|---|---|---|

### 공식과 비공식을 갈라두는 이유

| 성격 | 출처 | 성질 |
|---|---|---|

공개 프록시 네 곳이 한꺼번에 죽은 것이 그 예입니다.
**판단에 직결되는 값(시세 · 차트 · 기본 지표)은 공식에서만** 받고,
비공식은 **없어도 판단에 지장 없는 보조 정보**에만 쓰는 편이 안전합니다.

## 5-1. 공시 — 붙여 놓은 것 (2026-09-14)

`server/dart.py` 가 맡습니다. 브라우저는 `/api/dart/*` 로만 묻습니다.

| 무엇 | 어떻게 | 얼마나 |
|---|---|---|
| 기업 대응표 | OpenDART `corpCode.xml` (ZIP) | 하루 1회 · 상장사 3,990개 |
| 감시 대상 200종목 | 네이버 시가총액 순위 | 하루 1회 · 2회 호출 |
| 공시 목록 | OpenDART `list.json` (코스피 전체) | 평일 07:00~20:00 · 5분마다 |

### 왜 기간 조회인가

종목마다 따로 물으면 200종목 × 288번 = **57,600건/일** 로 하루 한도(약 20,000건)를
넘깁니다. 기간으로 한 번에 받아 우리 쪽에서 거르면 **약 1,150건/일**, 한도의 6% 입니다.

### 감시 대상 200종목을 네이버에서 받는 이유

한국투자증권 시가총액 순위 API(`/uapi/domestic-stock/v1/ranking/market-cap`,
tr_id `FHPST01740000`)는 **30건까지만** 돌려주고 연속조회용 `ctx_area` 가 응답에
없어 그 이상을 받을 수 없습니다 (2026-09-14 직접 호출해 확인).

네이버 `m.stock.naver.com/api/stocks/marketValue/KOSPI?page=N&pageSize=100` 은
100건씩 주고 `totalCount` 가 2,477 입니다. 200종목이면 2회면 됩니다.

**비공식 API 라 예고 없이 막힐 수 있습니다.** 다만 이 값은 위 원칙에 어긋나지
않습니다 — 시세가 아니라 "무엇을 지켜볼지" 를 고르는 데만 쓰이고, 순위가 조금
틀려도 감시 대상이 한두 종목 바뀔 뿐입니다. 못 받으면 직전 목록을 그대로 씁니다.
막히면 한국투자증권 30건으로 줄여서 버팁니다.

### 알림

관심종목 8개(`server/dart.py` 의 `WATCH_CODES`)에 공시가 올라오면 텔레그램으로
보냅니다. 종류를 가리지 않고 전부 보냅니다 (2026-09-14 지시 — "우선 다 보내주고
하면서 조절하자"). 처음 켜는 날 쌓여 있던 것은 보내지 않습니다.

### 알아둘 것

- OpenDART 는 **실시간 푸시가 없습니다.** 주기적으로 묻는 수밖에 없어서 최대 5분 늦습니다
- 키가 틀려도 HTTP 200 을 주고 본문 `status` 로 알려줍니다
  (`000` 정상 · `010` 미등록 키 · `013` 데이터 없음 · `020` 한도 초과)
- `corp_cls=Y` 로 코스피만 받습니다. 코스닥까지 보려면 `K` 를 한 번 더 불러야 합니다

## 5-2. 업종 · 순위 · 투자자 — 붙여 놓은 것 (2026-09-17)

`tr_id` · 파라미터 · 응답 필드 · 실제로 받은 값은 **`docs/kis-sector-investor.md`**
한 곳에 있습니다. 여기 다시 적지 않습니다 (「같은 값은 한 곳에만 둔다」).

| 화면의 칸 | 우리 API | KIS 호출 |
|---|---|---|
| 업종 등락률 | `/api/kis/sectors` | 시장당 1번 |
| 상승률 · 하락률 TOP | `/api/kis/movers` | 1번 |
| 외국인 · 기관 30일 추이 | `/api/kis/investor-flow` | 1번 (300영업일이 한 번에 온다) |
| 외국인 · 기관 순매수 상위 | `/api/kis/investor-top` | 2번 |
| 테마 | **없습니다** | — |

**테마만 못 붙였습니다.** KIS 국내주식 REST 에 테마 API 가 없습니다
(공식 저장소 엔드포인트 목록에 `theme` 이 하나도 없습니다).
네이버 `m.stock.naver.com/api/stocks/theme` 이 JSON 으로 오는 것까지는
확인했지만, 비공식이고 워커에서 열리는지 재보지 못해 **붙이지 않았습니다.**

**순매수 상위는 가집계입니다.** 증권사가 하루 네 번 입력한 누계치라
마감 뒤 확정치와 다를 수 있습니다. 응답의 `meta.provisional` 이 `true` 로
오므로 **화면에 그대로 적어야 합니다.**

## 6. 주의할 점

- **네이버 · 야후는 공개 API 가 아닙니다.** 문서가 없고 약관상 허용 여부가 불분명합니다.
  개인이 자기 화면에서 보는 용도를 넘어 서비스로 내보낼 계획이라면 다시 검토해야 합니다.
- 공공데이터포털 금융위 시세는 **하루 늦습니다.** 실시간 대체재가 아닙니다.
- 한 항목을 두 곳에서 받지 않습니다. 받을 곳을 바꿀 때는 화면의 출처 표시도 같이 바꿉니다.
