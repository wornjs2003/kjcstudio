다른 세션의 작업을 교차 검증한다. 아래 항목을 **순서대로, 빠짐없이** 확인한다.
검사 대상은 인자로 받은 것($ARGUMENTS)이며, 없으면 아직 커밋되지 않은 변경 전체를 본다.

## 0. 범위 파악

- `git status --short` 로 누가 무엇을 들고 있는지 본다
- `git log --oneline -5` 로 최근에 무엇이 들어갔는지 본다
- **내 작업분과 남의 작업분을 먼저 갈라놓는다.** 남의 것은 읽기만 한다

## 1. 짝이 맞는가 (가장 자주 깨지는 곳)

한쪽만 고치고 끝난 것이 없는지 본다.

- `holdings/server/kis_proxy.py` ↔ `holdings/worker/kis-worker.js`
  로컬과 배포본이 **같은 판정, 같은 값**을 내야 한다
  (실제 사고: 시세 시장구분을 한쪽만 고치면 숫자가 갈린다)
- `js/data/market.js` 의 `PRIORITY_CODES` ↔ 서버·워커의 `FAST_CODES`
- 상수를 새로 만들었다면 그 상수를 쓰는 곳이 전부 바뀌었는지

## 2. 문서와 코드가 일치하는가

- `CLAUDE.md`(루트·holdings)에 적힌 값이 코드의 실제 값과 같은가
  (실제 사고: 문서는 다크 테마·accent `#4f7eff`, 코드는 라이트·`#3a6ae8` 였다)
- 규칙을 새로 정했으면 MD에 적혔는가. 적었으면 코드가 그 규칙대로인가

## 3. 추측으로 쓴 곳이 없는가

`CLAUDE.md` 의 추측 금지 규칙 위반을 찾는다.

- 외부 서비스의 화면 경로·메뉴 이름·API 응답을 **확인 없이** 적어두지 않았는가
- 주석·문서에 "확인한 것 / 확인하지 못한 것" 이 갈려 있는가
- 의심스러우면 **직접 호출해서 확인한다.** 확인 못 하면 그렇게 적는다

## 4. 키가 새지 않는가

**소스 코드만 보면 놓친다.** 두 곳을 따로 봐야 한다.

### 4-1. 커밋에 들어갔는가

- 남의 작업분이 섞이지 않았는가 (`git show --stat`)
- 커밋 메시지에 **왜 그렇게 했는지**와 근거 수치가 있는가
- 비밀키·토큰·`.env`·`secrets.json` 이 들어가지 않았는가
- 추가된 줄 전체를 패턴으로 훑는다 — 16진수 40자(인증키) · `숫자:영문숫자`(봇 토큰) ·
  긴 숫자열(대화방 번호) · Base64 40자 이상 · JWT

### 4-2. 실행 중에 응답으로 새지 않는가 (2026-09-14 실제 사고)

**코드가 키를 담지 않아도 런타임이 담는다.**

실제로 있었던 일 — `fetch()` 가 실패하자 Cloudflare 가
`"Too many redirects.<요청한 URL>"` 이라는 메시지를 만들었고, 그 URL 에
`crtfc_key=<인증키 40자>` 가 들어 있었다. 코드는 `throw new Error(\`OpenDART HTTP ${res.status}\`)`
처럼 키를 안 담았는데도, 그 메시지를 그대로 저장해 `/api/dart/status` 응답으로 내보냈다.
`slice(0, 120)` 은 길이만 자를 뿐 내용을 가리지 못했다.

그래서 이렇게 본다.

- 외부 호출 오류(`catch (e)`)를 **그대로** 저장·반환·로그하는 곳이 있는가
- 그런 곳이 있으면 키·토큰이 섞일 수 있는 경로인가 (호출 URL 에 키가 붙는 API 인가)
- 진단용 응답(`status`·`health`·`stats`)에 오류 원문이 실리는가
- 걸러낸다면 `crtfc_key` · `appkey` · `appsecret` · `token` 류 쿼리스트링을 지우거나,
  런타임 메시지 대신 **우리가 만든 문구**로 바꾼다

**재권님께 진단 결과를 여쭐 때는, 키·토큰이 보이면 가리고 붙여넣어 달라고 먼저 말씀드린다.**
위 사고는 "나온 내용을 그대로 붙여넣어 주세요" 라고 한 탓에 대화 기록에까지 키가 남았고,
재발급을 해야 했다.

## 5. 실제로 도는가

문법만 보지 말고 돌려본다.

- JS: `node --check <파일>`
- Python: 임포트해서 핵심 함수를 **실제 값으로** 호출해 본다
- 서버가 필요하면 **다른 세션이 쓰는 포트를 피해** 띄운다
  (메인 8080 · holdings 8765 · 설립 8090 · 프로젝트 8091)

## 6. 재권님이 눈으로 볼 수 있는가

`CLAUDE.md` 의 작업 확인 규칙이다.

- 화면 변경이면 서버를 띄우고 브라우저를 열어둔다
- 숫자 변경이면 **바뀐 값을 실측해서** 표로 보여준다

## 보고

확인이 끝나면 재권님께 이렇게 보고한다.

- **확인한 것** — 항목별로 통과 여부
- **문제** — 있으면 파일·줄 번호와 함께. 없으면 "없음"
- **확인하지 못한 것** — 반드시 따로 적는다

문제를 찾으면 **해당 세션에도 `SendMessage` 로 알린다.** 남의 파일은 고치지 않는다.
마지막으로, 그 세션이 아직 작업 중이면 `notify_when_idle` 을 다시 걸어둔다.
