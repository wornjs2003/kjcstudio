다른 세션의 작업을 교차 검증한다. 아래 항목을 **순서대로, 빠짐없이** 확인한다.
검사 대상은 인자로 받은 것($ARGUMENTS)이며, 없으면 아직 커밋되지 않은 변경 전체를 본다.

## 0. 범위 파악

- `git status --short` 로 누가 무엇을 들고 있는지 본다
- `git log --oneline -5` 로 최근에 무엇이 들어갔는지 본다
- **내 작업분과 남의 작업분을 먼저 갈라놓는다.** 남의 것은 읽기만 한다

## 1. 짝이 맞는가 (가장 자주 깨지는 곳)

한쪽만 고치고 끝난 것이 없는지 본다.

### 먼저 **목록**을 맞춘다 (값보다 먼저)

한쪽에만 있는 경로는 비교 대상에 오르지 않는다. 그래서 값만 대조하면 못 본다.

    diff \
      <(grep -oE '(route|dartRoute) === "[^"]*"' holdings/worker/kis-worker.js \
         | sed 's/.*"\(.*\)"/\1/' | sort -u) \
      <(grep -oE 'route == "[^"]*"' holdings/server/kis_proxy.py \
         | sed 's/.*"\(.*\)"/\1/' | sort -u) \
      && echo "라우트 목록 일치"

**차이가 한 줄이라도 나오면 그게 사고다.** 화면(`holdings/js/data/live.js`)이
부르는 경로가 양쪽에 다 있는지도 함께 본다.

    grep -rho "/api/[a-z-]*/[a-z-]*" holdings/js/ --include="*.js" | grep -v vendor | sort -u

**`js/` 전체를 훑는다.** 전에는 `js/data/*.js js/*.js` 만 봤는데, 2026-09-15 에
`js/components/schedule.js` 가 부르는 `/api/dart/members` 를 놓칠 뻔했다.
폴더를 하나씩 적으면 새 폴더가 생길 때마다 구멍이 난다.

**워커는 변수가 둘이다.** KIS 는 `route`, 공시는 `dartRoute` 로 받는다
(`kis-worker.js:1147`·`1152`). `route` 만 뽑으면 공시 4개가 "워커에 없다" 는
헛경보로 나온다. 2026-09-14 에 이 항목을 처음 쓰면서 실제로 그랬다.

실제 사고 (2026-09-14) — `f248d77` 이 화면을 `/api/kis/quotes` 로 바꾸면서
로컬 서버에만 라우트를 넣었다. 워커에 없어서 배포본이 404 를 냈고, 현재가·전일대비가
전부 빈칸이 됐다. 로컬에서는 멀쩡해 보였다. 검증에서 통과시키고 푸시까지 했다.

### 그다음 **값**을 맞춘다

- `holdings/server/kis_proxy.py` ↔ `holdings/worker/kis-worker.js`
  로컬과 배포본이 **같은 판정, 같은 값**을 내야 한다
  (실제 사고: 시세 시장구분을 한쪽만 고치면 숫자가 갈린다)
- 응답 항목 이름이 한 글자라도 다르면 안 된다. 화면은 같은 코드로 둘 다 읽는다
- `js/data/market.js` 의 `PRIORITY_CODES` ↔ 서버·워커의 `FAST_CODES`
- 상수를 새로 만들었다면 그 상수를 쓰는 곳이 전부 바뀌었는지

## 2. 문서와 코드가 일치하는가

- `CLAUDE.md`(루트·holdings)에 적힌 값이 코드의 실제 값과 같은가
  (실제 사고: 문서는 다크 테마·accent `#4f7eff`, 코드는 라이트·`#3a6ae8` 였다)
- 규칙을 새로 정했으면 MD에 적혔는가. 적었으면 코드가 그 규칙대로인가

### 값만 보지 말고 **개수**를 센다 (2026-09-16 추가)

위 항목은 **값이 다른 것**을 잡는다. 그런데 갈리는 방식이 하나 더 있다 —
**항목이 통째로 빠지는 것**이다. 값 대조로는 안 잡힌다.

같은 룰이 두 곳 이상에 적혀 있으면 **양쪽의 개수를 센다.**

    문서의 목록 항목 수  ==  코드 주석의 목록 항목 수
    「위 세 가지」 같은 개수 문구도 함께 고쳐졌는가

실제 사고 (2026-09-16) — 재권님이 「닫지않는다로해줘」 라고 정하셨고
`tools/show-window.py` 의 주석은 「하지 않는 일 **넷**」 으로 고쳐졌는데,
`CLAUDE.md` 의 목록은 **셋**인 채로 남았다. 내가 그 커밋을 검증하면서
「닫기 코드가 0곳인가」만 세고 문서 목록은 안 봤다. **목록이 셋인 채로도
글이 자연스러워서** 읽어도 안 걸렸다.

그래서 이렇게 본다.

- 룰을 **더했거나 없앴으면**, 그것을 적어둔 **모든 자리**를 찾아 개수를 맞춘다
- 코드만 고치고 룰 문서를 안 고친 것이 아닌지 본다. **반대도 본다**
- 「위 N 가지」 · 「셋이다」 처럼 **개수를 말하는 문장**이 같이 안 고쳐지기 쉽다

`debugging/check.py` 는 **경로**를 검사하지 개수는 검사하지 않는다.
경로 오류는 그것이 잡아주지만 이 종류는 아무것도 안 잡는다. 사람이 세야 한다.

### 크기·간격을 바꿨다면 **찍어서 잰다** (2026-09-17 추가)

값을 대조하는 것으로는 모자란 종류가 하나 더 있다. **적힌 값과 그려진 값이
다른 것**이다.

    「470px 로 적혀 있다」   →  파일을 열면 보인다
    「실제로 470px 이다」   →  화면을 찍어야 보인다

실제 사고 (2026-09-17) — 모달 차트 높이를 470 → 620 → 1240 으로 올렸는데
**한 번도 적용된 적이 없었다.** `flex: 1` 이 `flex-basis: 0%` 를 품고 있어서
`height` 가 무시되고 `min-height: 250px` 가 바닥을 잡고 있었다. 내가 그 커밋을
검증하면서 **「값이 그렇게 적혀 있다」만 확인하고 화면은 안 봤다.** 재권님이
"차트의 세로 높이는왜 계속 안키워?" 하고 물으셔서 드러났다.

그래서 **크기·높이·간격·개수가 바뀌었다고 하면 전후를 찍어서 잰다.**

    chrome --headless=new --disable-gpu --hide-scrollbars \
           --window-size=1500,1000 --virtual-time-budget=8000 \
           --screenshot=<파일> <주소>

- **같은 폭·같은 조건**으로 전후를 찍는다. 조건이 다르면 비교가 안 된다
- 그림에서 픽셀을 읽는 것이라 ±10px 쯤 오차가 있다. **커졌나 안 커졌나**는 분명하다
- 이 방법으로 **로컬 화면의 JS 오류**도 잡을 수 있다 —
  `--enable-logging=stderr --log-level=0 --dump-dom` 을 붙이면 콘솔이 나온다.
  배포본은 Access 뒤라 안 되지만 로컬은 된다 (2026-09-16 에 데일리분석 문안이
  `TypeError` 로 안 만들어지던 것을 이렇게 잡았다)
- **헤드리스는 폭 512px 아래로 못 내려간다.** 폰 전용 규칙은 재권님이 실기나
  F12 디바이스 모드로 보셔야 판정된다. 그 부분은 「확인하지 못한 것」에 적는다

### DOM 이 맞아도 **CSS 가 걸리는지** 따로 본다 (2026-09-17 추가)

바로 위가 「적힌 값과 그려진 값이 다른 것」이라면, 이것은 **DOM 과 CSS 가
따로 노는 것**이다. 요소도 맞고 클래스도 맞는데 화면은 그대로다.

2026-09-17 하루에 같은 모양이 세 번 났다. 셋 다 검사기는 통과시켰다.

    hidden 을 붙였는데 안 숨었다     `.kh-ix { display: flex }` 가 브라우저 기본
                                    `[hidden]{display:none}` 을 이긴다.
                                    **작성자 스타일이 항상 UA 스타일보다 세다**
    클래스가 빠져 규칙이 안 걸렸다   `<tr class="is-active">` 는 하나뿐인데
                                    부모에 `kh-rank` 가 없어 규칙이 안 닿았다.
                                    내가 **DOM 만 세고 통과**시켰다
    클래스를 붙여 다른 규칙이 왔다   같은 이름에 **배치**와 **모양**이 같이
                                    걸려 있어, 표 규칙을 살리려다 grid 가 따라왔다

그래서 이렇게 본다.

- **클래스를 더하거나 뺐으면 그 이름에 걸린 규칙을 전부 찾는다.**
  `grep -rn "\.클래스이름" <구역>/css/` — 한 파일이 아니라 **그 구역 css 전부**다
- 한 이름에 **배치**(`display` · `grid-template` · `flex`)와 **모양**(색 · 글꼴 ·
  테두리)이 섞여 있으면 붙이는 순간 둘 다 온다. 그 자리를 짚어준다
- `hidden` · `disabled` 처럼 **브라우저 기본 스타일에 기대는 속성**을 쓰면,
  우리 CSS 에 `display` 가 있는지 본다. 있으면 우리 것이 이긴다

#### 최소 재현에는 **부모 사슬**을 넣는다

CSS 는 부모가 정한다. 요소만 떼어내 재현하면 **반대 결론이 나온다.**

같은 날 실제로 그랬다 — 카드가 4열로 쪼개진다고 보고했는데, `.kh-side-wrap`
한 겹을 빼먹은 것이었다. 실제로는 `.kh-side-wrap > .kh-card`(0,2,0)가
`.kh-rank`(0,1,0)를 이기고 있어 **멀쩡했다.**

    <link> 로 실제 CSS 를 그대로 불러온다      (localhost 절대주소로 걸면 된다)
    부모를 HTML 에 적힌 순서 그대로 쌓는다
    getBoundingClientRect() 로 top·width 를 잰다

#### 한 파일만 보고 「전체에 없다」고 하지 않는다

같은 날 `.kh-rank-card` 규칙을 `home.css` 에서만 찾고 **「저장소 전체에 0개」**
라고 단정했다. `frame.css` 에 있었다. **좁게 보고 넓게 말한 것**이라
「추측 금지」에 걸린다. 범위를 말할 때는 **찾은 범위를 같이 적는다.**

## 4. 키가 새지 않는가

**소스 코드만 보면 놓친다.** 두 곳을 따로 봐야 한다.

### 4-1. 커밋에 들어갔는가

- 남의 작업분이 섞이지 않았는가 (`git show --stat`)
- 커밋 메시지에 **왜 그렇게 했는지**와 근거 수치가 있는가
- 비밀키·토큰·`.env`·`secrets.json` 이 들어가지 않았는가
- 추가된 줄 전체를 패턴으로 훑는다 — 16진수 40자(인증키) · `숫자:영문숫자`(봇 토큰) ·
  긴 숫자열(대화방 번호) · Base64 40자 이상 · JWT

### 4-2. 실행 중에 응답으로 새지 않는가 (2026-09-14 실제 사고)

**코드가 키를 담지 않아도 런타임이 담는다.**

실제로 있었던 일 — `fetch()` 가 실패하자 Cloudflare 가
`"Too many redirects.<요청한 URL>"` 이라는 메시지를 만들었고, 그 URL 에
`crtfc_key=<인증키 40자>` 가 들어 있었다. 코드는 `throw new Error(\`OpenDART HTTP ${res.status}\`)`
처럼 키를 안 담았는데도, 그 메시지를 그대로 저장해 `/api/dart/status` 응답으로 내보냈다.
`slice(0, 120)` 은 길이만 자를 뿐 내용을 가리지 못했다.

그래서 이렇게 본다.

- 외부 호출 오류(`catch (e)`)를 **그대로** 저장·반환·로그하는 곳이 있는가
- 그런 곳이 있으면 키·토큰이 섞일 수 있는 경로인가 (호출 URL 에 키가 붙는 API 인가)
- 진단용 응답(`status`·`health`·`stats`)에 오류 원문이 실리는가
- 걸러낸다면 `crtfc_key` · `appkey` · `appsecret` · `token` 류 쿼리스트링을 지우거나,
  런타임 메시지 대신 **우리가 만든 문구**로 바꾼다

**재권님께 진단 결과를 여쭐 때는, 키·토큰이 보이면 가리고 붙여넣어 달라고 먼저 말씀드린다.**
위 사고는 "나온 내용을 그대로 붙여넣어 주세요" 라고 한 탓에 대화 기록에까지 키가 남았고,
재발급을 해야 했다.

## 6. 재권님이 눈으로 볼 수 있는가

`CLAUDE.md` 의 작업 확인 규칙이다.

- 화면 변경이면 서버를 띄우고 브라우저를 열어둔다
- 숫자 변경이면 **바뀐 값을 실측해서** 표로 보여준다
- **배포에 영향 있는 변경이면 배포본 주소까지 띄운다.** 로컬만 보고 끝내지 않는다
  (실제 사고 2026-09-14: 로컬에서 확인하고 "됩니다" 로 넘겼는데 배포본은 깨져 있었다.
   워커·Pages 를 건드렸거나, 화면이 부르는 경로가 바뀌었으면 여기에 해당한다)
- `thekjcstudio.com` 은 **Cloudflare Access 뒤에 있어 내 `curl` 은 302 로 돌아온다.**
  배포본 확인은 재권님 브라우저로만 된다. 주소를 띄워드리고, **무엇이 보이면 정상인지**
  판정표를 함께 드린다. 내가 확인한 것처럼 적지 않는다

### 배포본이 옛것으로 보이면 **캐시를 먼저 의심한다** (2026-09-17 추가)

배포본에서 이상한 것을 보시면 **코드를 파기 전에 캐시부터 가른다.**
가르는 법은 한 줄이다.

    Ctrl+Shift+R 로 고쳐진다   →  브라우저 캐시다. 코드는 멀쩡하다
    그래도 그대로다            →  그때 코드를 본다

**콘솔 오류의 줄 번호가 배포된 파일과 안 맞으면 그것이 증거다.**
2026-09-17 에 `paintRows (home.js:479)` 로 찍혔는데 그 판의 실제 위치는
632줄이었다. 브라우저가 **옛 JS 를 새 HTML 과 함께** 돌리고 있었다.

    git show <배포된 해시>:<파일> | grep -n "^function <함수이름>"

**원인은 Cloudflare 의 `Browser Cache TTL` 이 4시간이었던 것이다** (2026-09-17 실측).
Cloudflare 는 origin 의 `Cache-Control` 이 그 설정보다 **짧으면 덮어쓴다.**
`Caching → Configuration → Browser Cache TTL` 을 `Respect Existing Headers` 로
바꿔 GitHub Pages 값을 따르게 했다.

**버전 쿼리(`?v=`)로는 못 막는다.** `<script type="module">` 이 import 하는
파일에는 쿼리가 안 붙는다 — 저장소에 상대 import 가 44곳이라,
**HTML 과 진입 파일만 새것이 되고 나머지는 옛것**인 상태가 된다.
오늘 난 오류가 정확히 그 모양이다.

## 7. 푸시 직전 — 올라갈 것을 전부 본다

**`git push` 는 브랜치 전체를 올린다.** 내 커밋만 올린다고 생각하면 안 된다.
내 커밋 아래에 남의 커밋이 있으면 **함께 간다.**

    git log --oneline origin/main..main

여기 나온 것이 전부 올라간다. **하나씩 다 검증했는지 확인한다.**
검증 안 한 것이 섞여 있으면 그것부터 본다.

실제 사고 (2026-09-15) — 내 커밋 하나를 올린다고 생각하고 푸시했는데,
`주식페이지_개발` 의 커밋 3건이 그 아래 있어서 함께 올라갔다. 검증 전이었다.
푸시 절차(검증 → 보고 → 지시 → 푸시)를 건너뛴 셈이다. 뒤늦게 검증해 전부
통과였지만 순서가 틀렸다. 세션이 셋이라 또 난다.

## 보고

확인이 끝나면 재권님께 이렇게 보고한다.

- **확인한 것** — 항목별로 통과 여부
- **문제** — 있으면 파일·줄 번호와 함께. 없으면 "없음"
- **확인하지 못한 것** — 반드시 따로 적는다

문제를 찾으면 **해당 세션에도 `SendMessage` 로 알린다.** 남의 파일은 고치지 않는다.
마지막으로, 그 세션이 아직 작업 중이면 `notify_when_idle` 을 다시 걸어둔다.
