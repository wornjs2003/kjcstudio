#### 저장은 이 PC 안에만 둔다 (2026-09-18 지시)

**git 에 올리지 않는다.** 나중에 맥미니에 서버를 세우면 **백업서버**를 만들어
거기서 관리한다. 그때까지는 이 PC 안이다.

그래서 설계에서 두 가지가 중요해진다.

| 무엇 | 왜 |
|---|---|
| **한 파일에 모은다** | 맥미니로 옮길 때 그 파일만 가져가면 된다 |
| **경로를 한 곳에서 정한다** | 서버가 생기면 그 한 곳만 고친다 |
| **저장할 때마다 직전 것을 남긴다** | git 이 없으니 **되살릴 방법이 그것뿐이다** |

마지막이 특히 그렇다. git 을 안 쓰면 실수로 지운 것을 되돌릴 수 없다.
`debugging/history/` 가 같은 방식으로 회차를 쌓고 있다 (161개, gitignore).

**이것은 화면 몫이 아니라 API 몫이다.** 브라우저는 파일을 못 쓴다.
`debugging/history/` 를 쌓는 것도 `check.py` 쪽이다. **PUT 을 받을 때
직전 것을 옮기면 된다.** 화면 쪽에 적어두면 아무도 못 한다.

**API 모양을 프로젝트 보드와 같게 둔다.** 맥미니 서버가 나중에 같은 모양으로
응답하면 **화면은 한 줄도 안 고치고** 주소만 바꾸면 된다. 경로도 `/api/board/doc/<이름>`
을 그대로 쓴다 — 모양이 같아야 아래 공용 모듈에 분기가 안 생긴다.

**저장 계층은 보드 셋이 함께 쓴다.** 프로젝트 · AI 작업 · 검수 보드로 **세 번째**라,
「같은 종류의 복제가 하나 더 나오면 합치거나 만든다」 에 걸린다.

    한 곳에 모을 것   persistLocal · loadFromServer · syncToServer · serverAlive · 경로

**합치는 것은 화면이 아니라 이 층 하나다.** 맥미니로 옮길 때 **그 한 파일만**
고치면 셋이 함께 따라온다. 지금 구조로는 세 군데를 고쳐야 한다.

**「구역/마지막 조각」 으로 센다 — 이름 규칙에 기대지 않는다.** 마지막 조각만 세면 주식(`domestic-stock`)과 선물(`domestic-futureoption`)의 `inquire-price` 가 **한 칸에 섞인다** — 2026-10-02 실측으로 그 칸 11,201 중 선물이 8,099 였다(개발2 가 찾음). 구역을 붙이면 경로 열다섯이 다 갈린다. 처음에 `inquire-` 로 적었다가 **멀티 시세
(`intstock-multprice`)가 통째로 빠져 26% 를 놓쳤고**, 놓친 것이 분모에서도 빠져 남은 것이 부풀어
보였다 — 그런데 그 부푼 값이 다른 실측과 비슷해서 **「맞는 것 같다」 로 보였다**(주식페이지_개발1 이
반대쪽을 세어 찾음). 합이 `[KIS]` 줄 수와 맞는지 한 번 본다.

**이 비율은 시각과 열린 화면에 따라 크게 바뀐다** — 2026-10-01 에 세 시간 사이 5분봉이 21.9% → 6.6%
(미리 받기는 아침에 몰리고, 외부접속 화면이 켜져 있으면 지수·멀티가 치솟는다 · 창구 실측).
**무엇이 큰가를 정할 때는 그 자리에서 다시 센다.** 적어 둔 값으로 판단하지 않는다 — 세는 방법을
적어도 **그 방법이 흔들리는** 경우다.

**세션이 서버를 띄우면 죽는다 (2026-09-18 실측).** 세 가지로 해봤는데 전부
죽었다 — 세션에 묶기 · `Start-Process` · `start /min cmd /c`.
**셋의 공통점은 세션이 부모라는 것이다.** 8765 가 종일 사는 이유는
`startup.bat` 이 띄웠기 때문이다. **세션이 서버를 관리하려 하지 않는다.**

**`market.db` 는 지금 `journal_mode = delete` 다** (4.2MB, 2026-09-18 실측).
이 모드로 공유하면 **쓰는 동안 읽기가 막힌다.** `WAL` 로 바꾸면 여럿이 읽고
하나가 쓰는 것이 되는데, **쓰는 쪽이 여럿이면 WAL 이어도 부딪힌다.**
그래서 1 → 3 순서다.

**예산 설정과 실제 사용량은 다른 이야기다.** 1 이 끝나 실제 호출이 줄어도
`budgetPerSec` 설정은 그대로라, 네 서버가 동시에 몰리면 한도를 넘을 수 있다.
**둘 다 봐야 한다.**

### 중간서버를 실제로 돌릴 때 (2026-09-18 · 홈페이지_정리 판단)

- **합칠 순서는 먼저 올린 순이다.** 급한 순으로 하면 「누가 급한가」 를
  합치는 쪽이 판정하게 되는데, 그것은 `작업우선순위` 자리다
- **뒤처짐은 개수로 재지 않는다.** 스무 커밋 뒤여도 남의 파일만 바뀌었으면
  문제가 없다. **「올리기 직전 merge」 가 지켜지면 뒤처짐 자체는 문제가 아니다**
- **되돌려보낼 때 `staging` 을 되감지 않는다.** 되감으면 통과한 남의 작업까지
  사라진다. **그 커밋만 `revert`** 하면 그 세션이 고쳐서 다시 올릴 때 깨끗하게 얹힌다
- **화면 확인은 고친 파일이 닿는 곳만 본다.** 「전체를 본다」 와 「고친 것만 본다」
  사이의 답이고, **기계가 고를 수 있다** — 화면이 무엇을 `import` 하는지 따라가면
  「이 파일을 고치면 어느 화면이 바뀌나」 가 나온다

      chart.js 를 고쳤다   → index · stock
      frame.js 를 고쳤다   → 화면 전부
      daily.js 를 고쳤다   → daily 하나

  2026-09-18 에 이것 때문에 두 번 놓쳤다 — 같은 버그가 `daily.js` 와 `news.js`
  양쪽에 있었는데 한쪽만 고쳤고, `chart.js` 를 고치면서 첫 화면만 보고
  종목 화면은 안 봤다. **도구로 만들 값이 있다** (`tools/`, 개념정의).

### 되돌리는 길

    git worktree remove <폴더>        세션 폴더마다
    git branch -D staging work1 …

**폴더가 하나로 돌아간다.** 다만 옮겨간 세션은 **장바구니(인덱스)도 나뉘므로**
아래 「장바구니(인덱스)도 하나다 — 개발 폴더에서」 절이 그 세션에는 안 맞는다. **어느 세션이 옮겨갔는지
표에 적어 둔다.**

### 둘 다 정해졌다 (2026-09-22)

    전환 시점          **전환했다** — 아래 절을 「개발 폴더에서만」 으로 좁혔다

정해지면 지운다 — 「아직 안 정해진 자리는 빨간 바탕으로 남긴다」 와 같은 자리다.

### 창을 띄울 때 기존 창을 건드리지 않는다 (2026-09-16 지시)

**무엇을 무엇으로 여는지**가 먼저다.

| | |
|---|---|
| **① 띄우는 것** | 로컬 이미지 · 로컬 웹페이지 |
| **② 문자로 된 것** | **메모장으로 연다** |
| **③ 앞으로 꺼낼 때** | **그 프로그램의 창만 본다. 제목으로 짐작하지 않는다** |

**③ 이 따로 있는 이유** — 버그가 여는 자리가 아니라 **연 다음**에 있다.
이미지와 웹페이지는 새 창이 생겨서 「열기 전/후」 비교로 잡히는데,
**메모장은 탭으로 붙어서 새 창이 안 생긴다.** 그러면 제목으로 짐작하러 가고,
거기서 샌다. 2026-09-16 실측이다.

    'kis-worker.js' 로 찾음 → 1개 일치
    → kis-worker.js - KJCStudio - Visual Studio Code

**제목은 그 파일을 연 다른 프로그램도 갖고 있다.** 편집기에 열어 둔 파일을
띄우면 재권님이 쓰시던 편집기가 앞으로 튀어나오고, 1개라서 조건도 통과한다.
② 때문에 문자는 **항상** 이 길로 가므로 오히려 더 자주 난다.

같은 날 이 자리를 두 번 좁혔다 — **임의의 힌트 → 파일명 → 프로그램 + 파일명.**
앞의 둘은 **무엇으로 열었는지를 안 보고** 제목만 봤다는 점이 같았다.

프로세스 **이름**으로 거른다. `Popen` 이 준 PID 로는 안 된다 — 메모장이 탭
방식이라 그 프로세스는 기존 메모장에 넘기고 곧 끝나서, 쥐고 있던 PID 는
죽어 있고 그 PID 의 창도 없다.

새 창을 앞으로 꺼내는 것은 되지만, **재권님이 보고 계시던 창에는 손대지 않는다.**

- **기존 창을 최소화하지 않는다**
- **기존 창을 옮기거나 크기를 바꾸지 않는다**
- **제목으로 못 찾으면 아무 창도 건드리지 않는다**
- **기존 창을 닫지 않는다**
- **이미 띄운 것은 다시 열지 않는다.** 앞으로만 꺼내고 새로고침을 부탁드린다

세 번째가 핵심이다. 2026-09-16 에 제목 매칭이 빗나갔는데, 그때 「가장 최근에 뜬
Chrome」 을 대신 집어서 **재권님이 보고 계시던 Cloudflare 대시보드를 앞으로
꺼냈다.** 못 찾았으면 멈췄어야 했다.

**찾지 못하는 것은 괜찮고, 엉뚱한 창을 집는 것이 사고다.**

`SW_RESTORE` 는 **방금 내가 연 창에만** 쓴다. 그 창이 최소화된 채 열렸을 때
펴 주는 용도이고, 다른 창에는 쓰지 않는다.

#### 누가 띄운 창인지 제목에 남긴다 (2026-09-17 지시)

창을 여럿 띄워 두면 **어느 세션이 띄운 것인지 알 수 없다.** 2026-09-16 에
`CLAUDE.md` 창이 16개 쌓여 재권님이 "이 창 누가 띄웠냐" 고 물으셨다.

파일명 규칙(`temp/README.md`)만으로는 모자란다. **브라우저 탭에 뜨는 것은
파일명이 아니라 `<title>` 이다.**

`tools/show-window.py` 가 **알아서 붙인다.** 기억하지 않아도 된다.

    <title>지수 정리</title>   →   <title>개념정의 · 지수 정리</title>

- 세션 이름은 환경변수 `CLAUDE_CODE_SESSION_ID` 로 기록 파일을 찾아 읽는다.
  `tools/update-sessions.py` 와 같은 방식이다
- **저장소 파일은 고치지 않는다.** 화면에 나가는 제목이고 우리 것이 아니다.
  `temp/` 와 세션 임시 폴더만 손댄다. 그 밖이면 알리기만 한다
- 이미 붙어 있으면 그대로 둔다

**직접 열지도, P/Invoke 를 부르지도 않는다. 이것을 쓴다.**

    python3 tools/show-window.py <파일> [창제목의 일부]

위 「하지 않는 일」 이 이미 들어 있다. 제목이 **하나로 특정되지 않으면 아무 창도 건드리지 않는다** —
0개여도, 다섯 개가 걸려도 멈춘다. 직접 쓰면 그때마다 다시 지켜야 하고,
실제로 그러다 남의 창을 앞으로 꺼냈다.

**기억해야 지켜지는 룰은 지켜지지 않는다.** 그래서 도구로 옮겼다
(「같은 값은 한 곳에만 둔다」 의 대조 도구와 같은 생각이다).

#### 이미 띄운 것을 다시 보여드릴 때는 새로 열지 않는다 (2026-09-18 지시)

**다섯 번째가 오늘 생겼다.** 그 전에는 네 번째가 「닫지 않는다. **항상 새 창으로
연다**」 한 줄이었다. **둘은 다른 이야기인데 한 줄에 묶여 있었다** —
닫지 않는 것은 재권님 창을 지키려는 것이고, 매번 새로 여는 것은 그 결과가 아니다.

그 한 줄이 **창을 쌓으라고 시키고 있었다.** 그래서 「새 탭 그만 열겠습니다」 는
지킬 수 없는 약속이었다 — 지키면 룰을 어기는 상태였다.

    2026-09-16   CLAUDE.md 창 16개. 재권님이 "이 창 누가 띄웠냐" 고 물으셨다
    2026-09-18   md-diff 창 4개. 힌트 없이 못 찾아 다시 부른 것이 쌓였다

**이미 떠 있으면 `tools/show-window.py` 가 새로 열지 않는다.** 앞으로만 꺼내고
이렇게 알린다. 기억하지 않아도 된다.

    이미 떠 있어 앞으로만 꺼냈습니다: …
    **파일이 바뀌었으면 그 창에서 Ctrl+Shift+R 을 눌러 주십시오.**

**브라우저를 새로고침시킬 방법이 없다.** 주소를 여는 것밖에 못 해서, 이미 열린
탭을 갱신하려면 확장이나 디버깅 포트가 있어야 한다. 둘 다 안 열어 두었다.
**그래서 새로 여는 대신 「눌러 주십시오」 라고 말씀드리는 것이 맞다.**

같은 창이 **여럿** 떠 있으면 아무것도 열지 않고 몇 개인지 알린다. 이미 쌓여
있다는 뜻이라, 거기에 하나 더 얹지 않는다.

**여는 것도 도구로 한다.** `Start-Process <주소>` 나 `os.startfile` 을 직접
부르면 이 장치를 통째로 건너뛴다. 아래 「직접 P/Invoke 를 부르지 않는다」 는
**창을 조작하는 것**만 말하고 있었는데, **여는 것**이 빠져 있어서 그 길로 샜다.

**네 번째는 한 번 넣었다가 뺐다 (2026-09-16 지시).** 같은 파일을 두 번 띄우면
창이 쌓여서, 제목이 맞는 창을 닫고 새로 여는 방식을 넣었었다. **그 안전장치가 샜다.**

    힌트 '주식페이지_개발'   1개 일치 → 통과 → 재권님 세션 창
    힌트 'KJC'              3개 일치 → 통과 → VS Code · Holdings 창
    힌트 '설정'              2글자     → 막힘

**1개만 걸릴 때가 가장 안전해 보이는데 실제로는 가장 위험하다.** 그 하나가
재권님이 쓰시던 창이어도 장치를 전부 통과한다. 글자 수도 척도가 못 된다 —
한글 2글자가 영어 3글자보다 훨씬 특이하다.

    창이 쌓이는 것은 X 를 눌러 닫으면 된다.
    닫혀버린 창은 되돌릴 수 없다.

**재권님 화면에 우리 흔적을 남기지 않는다.** 이 절 전체가 그 이야기다.

#### 시험하고 나서 파일을 지우지 않는다 (2026-09-16)

**메모장은 탭으로 붙어 오래 남는다.** 시험 파일을 지우면 그 탭이 다음에 파일을
다시 읽으려다 **재권님 화면에 경고창을 띄운다.**

    C:\...\scratchpad\opentest.md 파일을 찾을 수 없습니다.   [확인]

2026-09-16 에 실제로 났고, 재권님이 스크린샷을 보내시며 "이거 뭐야?" 하고 물으셨다.

- **시험 파일은 `scratchpad` 에 만들고 그대로 둔다.** 세션 임시 폴더라
  재권님 화면에 나오지 않는다. **아무것도 안 하면 되므로 잊을 일이 없다**
- 굳이 지워야 하면 **창(탭)을 먼저 닫고 파일을 지운다.** 순서가 반대면
  메모장은 정상 동작하면서 팝업을 낸다
- 위 ② 때문에 문자는 **항상** 메모장으로 가므로, 시험할 때마다 탭이 하나씩 쌓인다
