### 뉴스를 받는 곳은 한 목록에서만 — 뉴스 분석이 원천 (2026-11-03 지시)

재권님 말씀 그대로다 — 「기사를 가져오는 곳들 룰도 잡아야 할거같은데. 주요 증권사 리포트나 발표 규모있는 포탈 등등 이여야 할거같아.

**쉬운 말로 — 뉴스 데이터에 넣는 기사는 정해 둔 「받는 곳 목록」 에서만 받는다. 목록에 넣고 빼는 것 · 시험으로 잠깐 받아 보는 것은 재권님이 정하신다.
네이버처럼 기사를 모아 주는 곳은 받는 곳이 아니라 「찾는 길」 이다 — 거기서 온 기사도 목록에 있는 언론사 것만 남긴다.**

**막으려는 것** — 작고 출처가 흐린 매체 기사가 섞여 분석이 흔들리는 것, 그리고 받는 곳을 화면마다 따로 정해 두 벌이 되는 것.

1. **원천은 Insight 「뉴스 분석」 화면이다** — 받는 곳 · 이슈 뽑기는 거기서 정한다. 한 건마다 매기는 여덟 칸(종목 대입)은 산업 분석이다(2026-11-12 · 바로 아래 절).
   홀딩스 종목 뉴스가 나중에 종목별로 받아 쓰는 결과는 산업 분석 것이다. 기사를 받아 쌓는 일은 서버가 한다(바로 위 「두 구역이 같은 값을 쓰면」 1번 그대로)
2. **받는 곳은 갈래 셋이다**
       (가) 1차 출처       공시 · 거래소 · 정부 · 한국은행
       (나) 주요 증권사 리포트
       (다) 언론            네이버뉴스 **콘텐츠 제휴** 매체인 종합지 · 경제지 · 통신사 + 해외 큰 통신사
       찾는 길            네이버처럼 여러 언론사 기사를 모아 주는 곳 — **목록에 적되, 그 길로 받은 기사는 언론사로 거른다**
                          (목록 (다) 에 있는 언론사만 남김 · 재권님 11-03 「가」)
                          **지금은 표시만 한다** — 기사를 빼지 않고 목록 안 · 밖 · 못 읽음을 붙여 센다. 목록에 더할 언론사를
                          재권님이 고르신 뒤 거른다(11-03 「나」 · 목록 파일 「찾는길」 칸)
   **찾는 길 자체는 받는 곳이 아니다 — 기사를 낸 언론사가 받는 곳이다.** 그래서 (가)(나)(다) 와 같은 급이 아니다
   - **거르는 셈은 서버 한 곳이다** — 도구 · 화면은 서버가 거른 값을 받는다(「두 구역이 같은 값을 쓰면」 1번). 길마다 따로 거르면 셈이 셋이 된다
   - **목록 (다) 항목에 네이버 언론사 번호 칸을 둔다** — 네이버 기사 주소 `n.news.naver.com/mnews/article/<번호>/…` 의 세 자리(2026-11-03 목록 근거 칸에서 확인 — 한국경제 015 · 매일경제 009 · 머니투데이 008). 이름은 길마다 표기가 갈려 번호로 견준다. 번호 칸이 없는 항목은 이름으로 견준다 — 칸은 2026-11-04 주식 레인이 더했다(`acb3794` · 셈은 `holdings/server/news.py` 의 `press_tally`)
   **빠지는 것** — 검색 제휴만 · 제휴 없음. 보도자료 받아쓰기 · 광고 · 행사 기사는 목록 안 매체여도 사람이 본다
3. **목록은 한 파일이다** — 어느 파일인지는 company-setup/README.md 의 뉴스 분석 절이 적는다. **고치는 것은 주식 레인**(서버가 읽는다).
   목록에 넣고 빼는 것은 재권님 결정 — 세션이 「괜찮아 보이는」 매체를 혼자 더하지 않는다
4. **보관 기간은 `holdings/server/news_store.py` 의 상수 한 곳이다** — 2026-11-03 재권님 「한 달」. 여기 숫자를 적지 않는다(「같은 값은 한 곳에만 둔다」)

**무엇이 검사하나 — 아직 없다.** 만들 수 있는 것 둘(「아직 검사가 없는 룰」 표) — 목록 항목에 갈래 · 근거가 비었나 · 찾는 길로 받은 기사의

**아직 안 잰 것** — 「주요 증권사」 의 선 · 지금 받는 언론사가 다 콘텐츠 제휴인지 · 증권사 리포트를 받을 길(약관 — 「아직」 이지 「영영」 이 아니다) ·

### 룰은 하나다 — 로컬만 다르게 정하지 않는다 (2026-09-23 지시)

재권님 말씀 그대로다 — **「룰은 하나니 로컬만은 아니고 다같은 룰로 정한다」.**

**기준과 구현을 가른다.**

| | 하나인가 |
|---|---|
| **기준** — 무엇을 지키나 (초당 몇 건 · 무엇을 가리나 · 언제 보내나) | **하나다** |
| **구현** — 어떻게 지키나 (파일 락 · 전역 변수 · 미들웨어) | **갈릴 수 있다** |

**갈리는 것은 구현이지 기준이 아니다.** 「로컬은 서버가 여섯이라」 는
**구현의 사정**이지 **기준을 바꿀 이유가 아니다.**

**구현이 갈리면 갈린다고 적는다.** 양쪽 코드에 서로를 가리키는 줄을 남기고,
**합칠 수 없으면 대조 도구를 만든다.**

**사례 — 같은 기준, 다른 구현** (아래 「워커」 줄은 2026-10-06 에 워커를 걷어내기 전의 모습이다 — 지금 구현은 로컬 하나다)

    기준   예외·오류는 가리고 내보낸다
    로컬   `secrets_guard.py` 의 `scrub` · `safe_message`
    워커   `kis-worker.js` 의 `scrub` · `safeErr`

    기준   KIS 를 초당 몇 건까지 부르나 — 값은 `kis_proxy.py` 의 `KIS_CALLS_PER_SEC` · 돌고 있는 값은 `/api/kis/stats` 의 `budgetPerSec`
    로컬   간격 배정 + **나가기 직전 「지난 1초 안 실제 나간 수」 창**(2026-10-03 `3a5df88` · 간격만으로는 늦게 깬 차례가 붙어 1초에 12건까지 몰렸다)
    워커   전역 변수 + 대기

**사례 — 기준이 갈린 것 (2026-09-23).** 로컬 간격만 **0.1초**로 내렸고
**워커는 200ms 그대로**였다. 그때는 되돌려서 다시 같아졌지만, **그 사이 어느 쪽을
보는지가 갈렸다.** **값을 바꿀 때 「여기만」 이 붙으면 그 자리를 의심한다.**

**2026-10-06 에 워커를 걷어내 이 갈림은 없어졌다** — 구현이 로컬 하나다. **워커를 되돌리는 날 이 값부터 맞춘다**
(「워커는 통과만 한다」).

**구조상 못 합치는 것이 있다.** 파일 락은 **로컬에서만** 된다 — Cloudflare
워커는 다른 기계라 그 파일을 못 본다. **그때도 기준은 하나로 두고,
「여기서는 이렇게 지킨다」 를 양쪽에 적는다.**

**「못 합친다」 와 「다르게 정한다」 는 다르다.** 앞은 사실이고 뒤는 선택이다.

### 예외·오류 문구가 밖으로 나가면 `scrub` 를 거친다 (2026-09-23)

**길이를 자르는 것과 내용을 가리는 것은 다른 일이다.**

    safe_message(e, N)   =   **scrub(e)[:N]**      가리고 자른다
    str(e)[:N]                                      **자르기만 한다**

2026-09-22 에 그것으로 사고가 났다 — 「`slice(0,120)` 은 길이만 자를 뿐
내용을 못 가린다」. 그 뒤 `holdings/server/secrets_guard.py` 가 생겼는데,
**새 파일이 그것을 안 쓰면 같은 일이 다시 난다.**

**가르는 선은 「무엇을 보내나」 다.**

| 보내는 것 | 거쳐야 하나 |
|---|---|
| **예외·오류 문구** | **반드시** — 키·토큰·쿼리스트링이 섞여 들어온다 |
| 시세·숫자·정해진 문구 | 아니다 — 비밀이 섞일 길이 없다 |

**밖은 넷이다** — 텔레그램 · Cloudflare KV · HTTP 응답 · **저장**.
**밖으로 나갈 것을 저장하는 것도 밖이다** — 저장본이 응답과 문안으로
그대로 나간다 (2026-09-23 실증 — 데일리 저장본이 API `200` 으로 나가고
그 안에 텔레그램 문안이 들어 있다).

**로그는 안이지만, 오류 문구는 로그에도 가려 적는다 (2026-09-23).**
**세션이 로그를 읽어 메시지로 옮긴다.** 그날 한 세션이 `logs/8765.log` 를
여러 번 읽고 **그 내용을 세션 간 메시지에 그대로 붙여 보냈다.** 거기 키가
섞인 오류가 있었으면 **「앱키·인증키는 세션 간 메시지로 주고받지 않는다」 를
어긴 것**이 된다.

**`logs/` 가 gitignore 인 것은 저장소 이야기다.** **읽는 사람이 옮기는 것은
막지 못한다.**

**다만 모든 `print` 를 거르지는 않는다.** 가르는 선은 위와 같다 —
**예외·오류 문구만**이다. `type(e).__name__` 만 찍는 자리까지 거르라고 하면
**고칠 것이 없는데 검사만 켜진다.**

**저장할 때 가려 두면 읽는 쪽이 안 가려도 된다.** `dart.py` 가 그 모양이다 —
`dart_last_error` 에 넣는 자리가 전부 `safe_message` 라, `heartbeat.py` 가
안 가려도 지금은 안전하다. **그래서 「지금 안전하다」 가 「앞으로 안전하다」 가
아니다** — 넣는 자리가 하나 늘면 그날 새어 나간다.

**2026-10-06 까지는 로컬과 워커 양쪽에 있었다** — 워커를 걷어내 지금은 로컬(`secrets_guard.py`) 하나다. 워커를 되돌리면 다시 두 곳이 된다.

**무엇이 검사하나** — **아직 없다. 만들면 「봐야 할 자리」 로 낸다.**

**안전한 것도 걸린다** — 호출 경로를 따라가야 갈리므로 **사람이 본다.**

### 한글을 출력하는 파이썬 도구에는 이 두 줄을 넣는다 (2026-09-16)

    if hasattr(sys.stdout, "reconfigure"):
        sys.stdout.reconfigure(encoding="utf-8", errors="replace")

윈도우 콘솔은 기본이 `cp949` 라 `—` 같은 글자에서 **`UnicodeEncodeError` 로 죽는다.**
계산은 다 맞고 출력 한 줄에서 죽으므로, 부르는 쪽은 그냥 실패로 읽는다.

**개발 중에는 멀쩡해 보인다.** 환경변수 `PYTHONIOENCODING` 이 걸린 셸에서
돌리면 콘솔이 UTF-8 이라 아무 일도 안 일어난다. 그 변수가 없는 곳 —
**`.bat` 이 부르는 `cmd` 가 정확히 그 자리다** — 에서만 터진다.
2026-09-16 에 `tools/show-window.py` 가 이렇게 나갔고, 다른 세션이 잡았다.

그래서 **시험은 환경변수를 지우고 한다.**

    PowerShell 에서 부른다
    cmd /c "set PYTHONIOENCODING=& chcp 949 > nul & python tools\<도구>.py"

**Git Bash 에서 `cmd /c` 를 그대로 쓰지 않는다 (2026-09-21 · 2026-09-22 원인 확정).**

**`/c` 가 `C:/` 로 바뀐다.** Git Bash 는 `/` 로 시작하는 인자를 윈도우 경로로
번역하는데, `cmd` 의 스위치도 그렇게 본다.

    (부른 것)   cmd /c "echo hello"
    (닿은 것)   cmd.exe C:/ "echo hello"     ← **스위치가 경로가 됐다**

그래서 `cmd` 가 **대화형으로 뜨고 안 끝난다.** 배너만 나오고 명령은 안 돈다.
`C:/` 를 경로로 읽으려 할 때는 재권님 화면에 이렇게 나온다.

    파일 이름, 디렉터리 이름 또는 볼륨 레이블 구문이 잘못되었습니다.

**어제는 「그냥 멈춘다」 로 적었는데 부정확했다.** 멈추는 것이 아니라
**대화형 셸이 떠서 안 끝나는 것**이다 — 2026-09-22 에 재권님이 그 오류를
보시고 물으셔서 갈렸다.

**둘 중 하나로 부른다 (2026-09-22 실측).**

    cmd //c "echo hello"                      슬래시를 둘로
    MSYS_NO_PATHCONV=1 cmd /c "echo hello"    번역을 끈다

**둘 다 `hello` 가 나온다.** 그냥 `cmd /c` 는 배너만 나온다.

같은 날 도구 **대부분**에 이 두 줄이 없어서 한꺼번에 넣었다.
새 도구를 만들 때도 넣는다 — 빠뜨리면 그 도구만 조용히 죽는다.

### `.bat` 안에는 한글을 쓰지 않는다 (2026-09-16)

`cmd` 는 배치 파일을 **한 줄 실행할 때마다 파일을 다시 열어 바이트 위치로 되짚는다.**
`chcp 65001` 로 코드페이지를 바꾸면 그 바이트 셈이 달라져서, 아래쪽에 한글이 있으면
위치가 밀려 **줄 한복판부터 실행된다.** 2026-09-16 에 실제로 이렇게 나왔다.

    '/*' is not recognized as an internal or external command
    'n' is not recognized as an internal or external command

세션 여는 단계까지 가지도 못하고 끝났다. 전에 "창이 하나 덜 열렸는데" 하신 것도
같은 원인일 가능성이 크다 — `resume-sessions.bat` 의 주석에 세션 이름이 한글로
박혀 있었다.

- `.bat` 본문은 **ASCII 로만 쓴다.** 한글 안내가 필요하면 파이썬 등에 맡기고
  `.bat` 은 그것을 부르기만 한다
- **`chcp` 는 빼지 않는다 (2026-09-21).** 밀림의 원인은 `chcp` 가 아니라
  **「`chcp` 뒤의 한글」** 이다. 본문이 ASCII 면 코드페이지가 바뀌어도
  되짚을 바이트가 안 어긋난다 — 저장소에 **`chcp` 가 있고 한글이 없는 `.bat` 이
  여럿 있고 전부 정상으로 돈다** (`startup.bat` 이 매일 다섯 서버를 띄운다).

  **빼면 오히려 위험하다.** 이 `.bat` 들이 부르는 파이썬은 `reconfigure(utf-8)` 로
  쓰는데, 콘솔이 cp949 면 그 UTF-8 바이트가 깨져 보인다. `chcp 65001` 이 짝을 맞춘다
- **`timeout /t N` 을 쓰지 않는다.** 입력이 리다이렉트된 채 실행되면
  `Input redirection is not supported` 로 즉시 죽는다.
  `ping -n N 127.0.0.1 > nul` 로 대신한다
